# 证书提醒与通知自检

Issue #7。配置页提供提醒开关、发送测试通知和打开系统设置。测试通知只在用户点击后提交；界面显示“已提交”，系统权限、专注模式和通知样式仍决定是否展示。通知正文不含网络名称、地址或证书身份；App 在前台也允许系统展示通知。

提醒开关表示应用内意愿，系统权限另行同步。回到前台、刷新配置及 App 运行期间每 5 分钟重新核对权限和补排。后台核对失败只在通知设置处提示，不覆盖连接错误；失败后同样按 5 分钟间隔重试，不随 3 秒状态轮询反复调用系统接口。系统撤销权限会撤回本应用证书计划，重新允许后可补排；隔离 --data-dir 实例不调用通知中心或写真实通知偏好。

## 排队与去重

完整计划按时间及 ID 稳定排序，每份证书最多 30／7／1 天及过期四项。先过滤已消费阈值，再取前 60 条送往系统，避免前 60 项已消费后阻塞后续计划。只有一个任务调用系统接口；过程中收到的变化保留最新计划，旧 add 返回后撤回过时请求并重查系统，再处理最新计划。排队的调用要等最新计划实际处理完（或失败）才返回，并得到同样的结果；因此关闭提醒返回时，系统队列中的本应用证书提醒已经撤回（#30）。首次成功读取网络列表之前不同步计划，以免把尚未加载的空列表当成“没有配置”，撤回提醒并清空去重历史。

被优先级挤出或因计划变化撤回的请求，会清除对应未消费历史，原触发时间过去后仍可补排。去重历史按当前计划 ID 收敛，上限随当前配置数增长（最多每份证书四个 ID），不再用固定 256 条上限遗忘旧提醒；配置删除／证书替换后清除无关记录。历史证明的是曾安排请求，不能当作用户已看到通知的证据。

显式关闭传空计划并清空历史；重新开启会重新安排当前到期阈值。App 退出后只能依赖已经提交给系统的队列，不会继续补排更多项目；需要运行 App 才能安排队列之外的提醒。未声称无限后台调度。

## 验证与限制

新增测试覆盖 300 份证书分批补排且持续开启时不重复、系统权限撤销后重排、60 条上限和其他通知 ID 保留、时区等价与到期边界、最新计划与迟到 add／pending 快照的竞争、优先级挤出后补排。两项竞争／补排测试均先在修复前失败，再修正通过；原有禁用与替换计划撤回测试保留。

完整 scripts/test.sh 通过 Go race、33 个 Swift 客户端测试和 4 个 AppKit 退出场景。生产设置组件已做隔离界面截图检查；隔离模型调用测试通知时返回 notifications_isolated，未发送真实通知。安全和架构审查提出的同步丢失、61 条队列竞争、撤回历史及测试文案问题已修正。

真实通知显示，以及系统设置中撤销／重新允许权限，已在 2026-11-05 完成实机验收，见 VALIDATION.md。
