# 节点与配置日常体验

2026-11-04 用户确认本批范围：节点搜索／筛选、地址复制与快捷测试、配置重命名。沿用既有原生系统控件、系统字体、8／12／20 pt 圆角、绿色连接和红色断开语义；网络行继续使用已有按压反馈，减少动态效果时停用动画。

选择完整的节点与配置改进，而非仅增加搜索框；Keychain 属于独立的存储迁移阶段。本批无第三方 API、账号、运行时或新服务，使用现有 SwiftUI 和普通配置后台。根组件协议与版本保持兼容，不升级当前安装。

```text
节点快照 → 本地搜索／状态筛选 → 分批展示 → 复制或既有受限探测
名称输入 → 普通后台校验 → 原子更新配置索引的显示名称
                              └→ 配置版本／凭据保持原样
```

名称存储在索引的可选 `displayName` 中，兼容旧索引；配置回滚保留此覆盖名称。重命名不创建凭据副本、不占用回滚版本、不改变连接摘要或原始文件，连接中亦可执行。更新已有配置时默认保留当前显示名称。名称去除首尾空白，拒绝空名称、控制字符及超过 160 个 UTF-8 字节的内容；界面给出可读错误。

节点按设备名或 IPv4／IPv6 地址搜索，支持多个关键词联合匹配和活动／待握手筛选。初次显示最多 50 条，按需增加；计数明确来源于本机记录，未匹配与无记录分别解释。复制始终使用完整地址，多地址节点可分别测试。搜索不会发出探测请求，也不把待握手与无回复解释为远端离线。

外部依赖故障不影响本地搜索与命名；节点增长时限制渲染数量。格式为增量添加字段，可切回旧版读取配置与凭据，旧版可能显示原版本名称。正常连接及清理不依赖新显示名。全部测试使用临时身份和存储，当前连接保持不动。

验证覆盖连接中的重命名、重复操作、无效输入、重开存储、旧索引、配置更新／回滚名称保留、凭据与摘要不变、名称／地址搜索、空结果、状态筛选、分页与复制目标一致。最后执行既有 Go race、Swift 与 AppKit 回归，并实际检查独立构建。

## 日志页（#56、#57）

工作区第四个页签「日志」（⌘4）分为两部分。内核日志以实时滚动方式显示：按时间顺序排列，最新在底部；打开页面后立即读取，之后每秒刷新一次。「自动滚动」默认开启，跟随最新条目；向上查看历史时可以关闭。读取 `logs` 时，普通后台会先向 helper 拉取一次新增条目，因此刷新不受 3 秒状态轮询限制。离开页面、电脑睡眠或退出时停止读取；上一次读取尚未完成时，不会发出新的请求。

```text
Nebula 内核 slog → helper 内白名单 handler（300 条环形缓冲）
  → 同一控制会话的应答附带新增条目（按会话游标增量）
  → 普通后台再次限额、重新编号并跨会话保留 → GUI「logs」请求
```

- **内核日志**：只保留白名单字段（错误、原因、节点 VPN／UDP 地址与来源 `from`、证书名称／指纹、握手与中继索引、握手阶段与耗时、接口、MTU 等）。Nebula 以 map 记录的嵌套值（如 `handshake`）按键展开后逐项过白名单；`cert`、`packet`、`header` 等其他字段不格式化、不保存，只计入“已隐藏”数量。消息上限 300 字符，字段值上限 200 字符，每条最多 12 个字段；含 PEM 标记或 `PRIVATE KEY` 的值替换为“已隐藏”。级别遵循配置的 `logging.level`，默认 info。
- **启动失败也可查看**：connect 失败的应答同样携带本次启动期间的日志，普通后台在 helper 会话关闭后仍保留，便于排查无法连接的原因。
- **范围**：日志只在本机界面显示，可手动复制；不写文件，不进入诊断导出（诊断导出仍不含节点地址）。日志只经发起连接的控制会话传递，不向其他本机用户开放。
- **连接事件**：仍为后台最近 100 条结构化事件码，与内核日志分开显示。

该协议字段使 helper 发布号升至 0.4.0；之后白名单扩充与 map 展开在 helper 内生效，再升至 0.4.1。旧 helper 不返回日志字段，界面显示“升级连接后台后可查看”；新 helper 搭配旧后台时，旧后台忽略该字段。

## 节点延迟监测（#44）

节点页可见、且当前网络的隧道已启动时，GUI 每 5 秒请求一轮 `sample`：对“活动隧道”节点的每个地址各发 1 个 ICMP echo。待握手节点不探测，因为探测流量会让 Nebula 主动发起握手。

```text
GUI（节点页可见，5 秒）→ 普通后台 sample：校验已连接、≤64 个地址、均在证书网段内、间隔 ≥2 秒
  → 并发 ≤8，每个等待 1 秒，整轮 ≤4 秒（超时的地址标为“未测量”）→ 每个地址：回复耗时／未回复／无法测量
```

- 采样只在普通后台执行，不经过 root helper；复用手动测试的 utun 绑定套接字，不会被局域网或其他 VPN 的路由抢答。
- GUI 只在内存中为每个地址保留本次连接最近 60 个样本（约 5 分钟）。断开、切换网络或重新连接时清空；不写入磁盘，不进入诊断导出，也不记入连接事件。
- 页面顶部的汇总卡片显示各地址最新回复的中位延迟、分级胶囊和按分级分段的条形图。每个节点行显示最新延迟和迷你折线，展开后显示详细曲线及最低、平均、最高、抖动、丢包和样本数。
- 分级：<50 ms 良好，<150 ms 一般，≥150 ms 较慢，未回复为“无回复”。文案只描述 ICMP 回复：未回复可能是节点禁止 ICMP，不代表远端离线。
- 离开节点页、电脑睡眠、退出或连接变化时停止采样；连接变化后到达的旧结果直接丢弃。
- 用户实机确认后，移除了手动的“节点连通测试”卡片、行内「测试」按钮和后台 `probe` 方法：活动节点由持续监测覆盖；待握手节点和列表外地址不再提供 ICMP 测试，以免触发握手。

## 登录时启动与自动连接（#63）

配置页的「启动与连接」提供两个独立开关，默认都关闭：

- **登录时打开 Nebula**：通过 `SMAppService.mainApp` 把 App 本身注册为登录项，不涉及 helper 或额外的守护进程。状态以系统为准：已启用、已关闭、需要在系统设置“登录项”中批准（提供跳转按钮），以及当前运行方式不支持（测试、预览、`--data-dir` 隔离运行）。以登录项方式启动时（根据启动 Apple Event 判断），主窗口在第一次出现时关闭，App 只在菜单栏运行；之后从菜单栏打开窗口不受影响。
- **启动后自动连接上次使用的网络**：App 每次启动执行一次。网络处于连接状态时，在 UserDefaults 中记录该网络的 ID，不存凭据。以下情况不自动连接，并在页面顶部说明原因：上次的网络已移除，连接后台未启用或需要升级。**从不自动弹出管理员授权窗口**。连接失败时，与手动连接一样交给“连接中断后自动恢复”重试，以应对登录初期网络尚未就绪的情况。

登录前（无人登录）建立隧道不在范围内：隧道由登录用户的 App 会话持有，App 退出即清理。若需要登录前连接，要改变 helper 的会话与授权模型，应另行设计。

## 菜单栏（#65）

菜单栏面板从上到下依次为：

- **标题与状态**。
- **网络卡片**：网络名称、本机 IP 与复制按钮。已连接时显示“已连接 N 分钟 · 活动节点 N · 中位 N ms”，每 30 秒刷新；未连接时显示状态说明。
- **整行主按钮**。
- **节点**：最多 6 个活动节点，每行显示名称、迷你折线和最新延迟；超过 6 个时提供“查看全部 N 个节点…”，直接打开主窗口的节点页。
- **切换网络**：导入了两个以上网络时出现。当前网络打勾，点击其他网络会先断开当前网络再连接所选网络；切换期间整个菜单不可操作。连接后台不可用时只打开主窗口，菜单不自行弹出授权窗口。
- **快捷开关**：「登录时打开 Nebula」「启动后自动连接上次使用的网络」，与配置页的开关一致。
- **底部菜单项**：打开 Nebula、导入网络、断开并退出。

菜单面板打开期间，与节点页一样每 5 秒采样一次活动节点延迟，两者共用同一份历史；两者都关闭时停止采样。

菜单栏图标仍是单色模板图像，随系统的浅色或深色菜单栏变化：
- **已连接**：实心标志。
- **连接中或自动恢复中**：标志变淡。
- **需要处理**：右上角带圆点，包括连接失败、有错误提示，或已有网络但连接后台未启用或需要升级。
- **未连接**：中心镂空。

每种状态都有对应的辅助功能描述。
