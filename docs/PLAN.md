# Nebula GUI 完整方案

整理日期：2026-11-03。下文保留实现前的讨论方案。用户随后已要求开始编码与本地验证；当前实现状态、已执行检查与限制见 [验证记录](VALIDATION.md) 和 [开发说明](DEVELOPMENT.md)。

## 1. 已确认的产品目标与开发位置

用户已明确以下要求：

- 优先服务普通用户，拿到配置后通过 GUI 一键连接。
- macOS 首发，后续依次跟进 iOS、Linux。
- 目前分发 `config.yaml`、`ca.cert`、主机证书和主机密钥。
- 首版只负责访问其他 Nebula 节点。
- 目前没有 Apple Developer Program 账号。
- 先调研、再讨论、最后实现；本次仅把方案落盘。
- 后续代码全部写入 `nebula-gui`，不在兄弟目录 `../nebula` 开发。

下文的界面行为、技术栈、阶段和阈值属于建议方案。用户尚未逐项确认，不应记录为已验收或已实现。

产品成功标准是普通用户不需要理解证书、Lighthouse 或后台进程，也无需打开终端，便能导入管理员提供的文件并访问另一个 Nebula 节点。内部开发验证可以使用命令行，不把该操作作为最终用户流程。

## 2. 首版范围

| 能力 | 建议行为 |
| --- | --- |
| 文件导入 | 选择 `config.yaml`，或选择／拖入包含配置与凭据的文件夹 |
| 自动校验 | 检查 YAML、引用文件、CA、证书有效期、签名与主机密钥匹配关系 |
| 配置保存 | 保存 App 管理的独立副本，删除源文件不影响已导入配置 |
| 网络连接 | 连接与断开，一次运行一个受管网络 |
| 菜单栏入口 | 查看状态、连接／断开、复制本机 Nebula IP、打开详情 |
| 多配置 | 保存多个配置并切换，更新已有配置时保留回滚版本 |
| 证书提醒 | 显示有效期，到期前提示；阈值建议为 30、7、1 天，产品实现前确认 |
| 故障帮助 | 展示明确原因、查看限额日志、导出脱敏诊断信息 |

首版不包含账号与控制平面、创建网络、签发证书、CA 管理、Lighthouse 部署、远程节点管理、防火墙规则编辑器、局域网网关、DNS 接管、全局流量代理或全网拓扑。

仅访问 Nebula 节点仍需要发现、握手、打洞或使用管理员配置的中继。禁止把已有中继连接配置误判为部署中继服务；普通客户端使用中继与 `relay.am_relay: true` 是不同需求。

## 3. 用户流程与界面

### 首次导入

空状态只提供导入入口与四类文件说明。用户选择 YAML 后，按引用查找关联文件；若 macOS 文件访问授权不覆盖关联文件所在目录，提示选择目录或补选文件。缺失文件按角色提示，不要求固定主机文件名。

校验通过后展示网络显示名称、证书中的设备名、Nebula IP／网段和有效期。网络显示名称可以修改，但不能修改证书声明。用户确认保存，再进入连接流程。首次系统授权应说明用途与需要批准的位置；取消后回到未连接状态，文件无需重新导入。

建议首版不加入 ZIP 解包，先完成目录与文件导入。ZIP 曾作为简化分发的备选项讨论，尚未纳入确认范围；如加入，需要处理路径穿越、符号链接与解压大小限制。

### 日常使用

菜单栏小窗展示当前配置、设备名称、Nebula IP、状态和连接按钮。正常连接时不展示底层参数。网络切换必须先完成旧连接清理，再启动新连接，不能同时修改两套受管路由。

关闭窗口保持连接，关闭界面与断开网络是不同操作。建议菜单提供退出界面、断开并退出；退出界面继续连接属于待验证的后台能力。用户重新打开 App 后从后台读取真实状态。注销与重启后自动连接不属于首版默认行为，验证版重启后恢复为未连接。

### 详情与帮助

详情分为身份与证书、本机已知节点、活动／待建立隧道、日志。地址和指纹可复制；私钥不显示，不提供一键复制。未知或后台不支持的指标显示未提供，不伪造延迟、带宽、丢包率。

节点列表明确来源于本机 HostMap 或待握手列表，不称作全网设备。没有隧道不等于节点离线；只有检测产生结果时才显示目标可达性，并展示检测时间。

视觉建议采用 macOS 原生工具风格，支持系统浅深色、键盘操作、辅助功能标签和文本状态。颜色用于辅助识别，不单独承担状态含义。

## 4. 配置导入与数据保存

导入时识别 `pki.ca`、`pki.cert`、`pki.key` 的文件引用或内嵌内容，避免仅按扩展名猜测。相对路径按源配置目录解析；处理绝对路径时明确请求相应文件访问权限。将可接受输入复制到受管存储，运行时只引用受管副本，不继续依赖下载目录。

原始文件保持不变。运行配置可以更新凭据路径、受管 socket 和日志位置；这些变更应有结构化记录。网络语义不能被静默改写；启动前重新校验运行配置。

校验至少包含：

1. YAML 可解析，配置结构和必要字段合法。
2. 文件角色明确，多个候选配置或重复证书不自动猜选。
3. CA 与主机证书能解析，主机证书受信任且在有效期内，密钥与证书匹配。
4. 受信任 CA 的约束、证书声明和本机内核版本兼容。
5. 提示系统时间可能导致的证书尚未生效或过期，不把它误报为网络故障。
6. 配置满足首版普通客户端范围，且不启用未批准的系统修改或额外管理监听接口。

首版只安装证书声明的 Nebula 网络所需路由。`tun.unsafe_routes`、默认路由、`dns.enabled: true`、Lighthouse／Relay 服务端角色及其他超范围能力在连接前报告具体配置键并拒绝启用，不静默忽略。已有客户端 `static_host_map`、Lighthouse 地址和远端 Relay 配置继续支持。

配置检查不能只运行 CLI `-test` 后把全部输出放进日志。该入口会打印合并配置，可能包含内嵌密钥；应优先复用结构化校验逻辑，并在捕获测试输出前完成脱敏设计。

配置元数据至少记录内部 ID、显示名称、设备名、地址、证书指纹、有效期、导入时间、受管版本、来源说明和内核版本。内部 ID 不仅用设备名或 IP 推断。更新时展示旧、新身份摘要，要求用户确认替换；不同身份不能自动覆盖。

保存流程使用临时副本、校验与原子替换。更新失败保留旧版本；正在连接的配置不被原地修改。密钥使用受保护存储，最终选择 Keychain 还是仅后台可读文件，要在后台访问模型确定后验证；暂不承诺两者都支持。

## 5. 状态必须来自实际后台

建议状态包括未配置、未连接、待授权、正在连接、已启动、正在断开和连接失败。系统网络不可用作为明确的原因或附加状态，避免把 Wi-Fi 断开显示成配置损坏。

后台进程创建成功不等于连接完成。已启动要求设备初始化成功且可查询受管后台；目标节点可达性单独展示。没有目标探测或 Lighthouse 响应证据时，不显示全网正常。

连接、断开和切换请求串行处理，并有超时、操作 ID 与重复请求保护。用户连接期间点击断开，应取消当前操作并完成清理；不能在迟到的启动响应到达后重新显示已连接。

断开完成需要后台退出或停止隧道、受管设备与路由清理完成。超时显示仍在清理或异常，不先显示断开成功。App 重启、后台崩溃和睡眠唤醒后重新同步状态。

## 6. 技术路线与当前建议

| 路线 | 现有代码复用 | 工作量 | 主要代价 |
| --- | --- | --- | --- |
| 原生 macOS UI＋现有 Go 进程 | CLI、IPC、Darwin 虚拟网卡和服务生命周期 | 相对较低 | 后台授权与安装升级必须验证；iOS 使用不同后台适配 |
| 原生 UI＋Network Extension＋Go 内核 | 内核、可注入虚拟网卡接口、部分 Apple 平台逻辑 | 相对较高 | 需要桥接验证、对应签名能力和各分发方式的扩展工程 |
| Flutter＋平台后台适配 | UI 可跨平台，内核继续使用 Go | 中高 | 新增 Dart／Flutter；各平台的授权、隧道与后台仍需分别开发 |

当前建议采用 SwiftUI／AppKit 原生界面与现有 Go 后台，先完成 macOS 本机验证版。macOS 最低版本建议从 13 起评估，以便使用现代服务管理与菜单栏 API；这是技术建议，不是用户已经确认的兼容范围。Apple Silicon 先完成本机验证，正式发布前再验证 Intel 与 Universal 打包。

本机验证不依赖 Apple Developer Program 会员，但不能推导出所有服务注册或扩展能力都无需会员。没有账号时，不把 Developer ID、公证、TestFlight 或 Network Extension 正式分发列为已具备条件。不给最终用户设计关闭 Gatekeeper、关闭 SIP 或反复执行提权命令的流程。

如果后台授权验证失败，只完成导入、校验和状态界面，并由开发者在隔离验证步骤中启动已有后台来检验通信；该产物必须称作开发验证版，不能冒称普通用户一键连接版。阻塞原因与需要的签名／安装条件记录后，再决定开通账号或调整方案。

### 建议的组件关系

```text
普通用户 GUI
    │ 结构化请求与状态
    ▼
本机连接管理接口
    │
    ├── 配置导入、版本与凭据存储
    │
    └── macOS 后台适配
            │ 受控生命周期操作／Nebula 本地 JSON IPC
            ▼
        固定版本 Nebula Go 进程
            │
            ▼
        utun、Nebula 路由、远端节点
```

连接管理接口负责状态与错误模型，UI 不直接拼接 shell 命令。后台适配负责启动、停止、崩溃回收、受管进程身份和 IPC 权限。配置 ID 是进程管理输入，不接受任意可执行文件或随意指定的配置路径。

现有 Nebula IPC 的管理范围有限：结构化控制命令不等于启动／停止系统服务的 API。需要单独实现生命周期管理，并只转发首版需要的只读诊断能力。

调研基于兄弟仓库提交 `fb4ef139cbb4af67d142c72083fb735f56460e50`。以下链接只供同级工作区阅读，不作为发布时的可移植依赖：

- [IPC 权限](../../nebula/localapi/access.go)：默认 `0600`，共享组模式意味着共享完整控制权限。
- [身份 HTTP API](../../nebula/info_api.go)：仅身份相关查询，不是完整管理 API。
- [后台入口](../../nebula/cmd/nebula-service/service.go)：现有生命周期实现参考，不能直接认定已满足普通用户授权。

后续构建记录内核提交与协议版本。当前内核包含本地扩展能力，不能默认任一上游发行包都兼容。首版采用固定版本内核；不允许用户任意挑选本机 `nebula` 可执行文件作为特权启动目标。

### 后台授权必须先验证

普通用户 GUI 不能直接连接 root 进程的默认 `0600` socket。不能通过 `chmod 666` 或给全部普通用户共享控制组来绕过这个问题。建议由受控后台桥接访问私有 socket，对 GUI 提供有限的接口，并校验调用者和配置归属。

macOS 13 及以后可考察 `SMAppService`，但注册、批准、签名和无付费账号的本机开发行为尚未实测。阶段一必须记录具体系统版本、签名方式、安装位置、批准步骤、重启结果与卸载结果。受管二进制及其上级目录不能被普通用户替换后继续由 root 执行。

导入的配置也会影响特权进程行为。后台必须重新校验配置、文件路径、日志输出、管理监听及受管字段，不直接运行 GUI 传来的任意 YAML。凭据只授予必要进程读取权限；本机通信鉴权必须覆盖多用户与伪造后台场景。

## 7. 分发与后续平台

| 阶段 | 分发目标与约束 |
| --- | --- |
| 本机验证 | 本地编译运行，验证权限、连接与恢复；不声称已具备普通用户安装体验 |
| macOS 正式版 | 再决定是否开通开发者账号；官网分发设计 Developer ID 签名、公证、安装升级与卸载，App Store 路线另行评估 |
| iOS | 使用 Network Extension；复用配置规则、错误模型及 Go 内核，重新适配隧道、密钥访问、文件导入和生命周期 |
| Linux | 复用 Go 内核、协议与配置语义；单独选择 UI、服务管理与发行包，桌面环境的托盘支持分别验证 |

Apple 的 Packet Tunnel 在 macOS App Store、macOS 直接分发和 iOS 的打包规则不同。官网 macOS 分发使用 System Extension，不能把 iOS App Extension 工程直接复制作为官网安装包。SwiftUI 不覆盖 Linux，未来 Linux UI 是独立工作量，不承诺三端一套界面。

不为了将来平台提前引入额外运行时。首版没有云 API、第三方控制平面、登录账号或 API Key 依赖。开发工具是 Xcode 与 Go；本机曾确认已安装 Xcode 和 Go 1.27.3，不代表已完成 SDK、签名或服务注册验证。

## 8. 建议目录与依赖边界

下面只定义后续组织方式，本次不创建这些代码工程：

| 路径 | 用途 |
| --- | --- |
| `apps/macos/` | 原生界面、菜单栏、文件选择和系统授权引导 |
| `backend/` | 本机连接管理、配置与校验、平台后台适配 |
| `tests/` | 需要跨组件运行的验证与生成式临时凭据 |
| `scripts/` | 构建、打包、实机验证与卸载脚本 |
| `docs/` | 方案、决策、调研与验证记录 |

`../nebula` 仅作为只读构建输入。初期可从固定提交构建到 `nebula-gui` 的忽略目录；正式构建需要补齐可复现的依赖获取与校验，不依赖开发者机器上的绝对路径。禁止把源码副本或整个内核提交历史复制入 GUI 工程来回避依赖管理。

整体实现将超过八个文件，并包含一个需要独立安装、授权与卸载设计的本机后台组件；这不是只加一个窗口的小改动。现阶段没有决定增加第二个常驻系统服务，后台桥接与现有进程的具体托管方式由阶段一结果决定。

## 9. 开发阶段与进入条件

### 阶段一：验证本机连接与权限

用户明确要求开始开发后再执行。开发者先构建固定版本内核到本仓库，生成隔离测试证书，验证启动、IPC 查询、断开和路由清理，再验证普通用户与特权后台的有限通信。系统安装或权限变更前列出具体动作与回退方法。

输出可复现的构建命令、系统与签名条件、成功／失败结果、进程和路由清理记录。必须证明关闭窗口后后台状态可恢复，且不能由其他本机用户管理连接。只有这一步成功，才把普通用户一键连接作为可交付目标；失败按第六节记录限制，不静默替换为终端操作。

### 阶段二：导入与最小 GUI

实现目录／文件导入、结构化校验、受管副本、设备摘要、单配置连接／断开、真实状态和明确错误。使用临时测试凭据，不提交真实主机密钥。入口不提供复杂网络参数编辑。

### 阶段三：日常使用与排障

加入菜单栏、多配置保存与串行切换、配置替换与回滚、到期提醒、节点详情、限额日志与诊断导出。后台不具备的指标不显示成零值测量结果。

### 阶段四：实机验收与发布决策

验证完整验收表，记录实际支持的 macOS 版本与架构。根据账号与分发选择完成签名、公证或明确维持本机验证版。首次安装、升级、失败回滚和卸载必须形成用户可执行流程。

本次文档整理不授权阶段一的代码、系统安装、服务注册、账号注册、付费或发布。

## 10. 验收矩阵

| 场景 | 通过条件 |
| --- | --- |
| 正常导入并连接 | 文件齐全，身份正确，访问测试 Nebula 节点成功 |
| 源目录删除或移动 | 受管副本仍可连接 |
| 缺失文件与权限拒绝 | 明确指出角色与原因，可补选或重试，不出现半成品配置 |
| YAML 错误、证书过期／未生效、密钥不匹配 | 启动前拒绝，日志与提示无密钥内容 |
| 超范围路由、DNS、服务端角色 | 显示具体字段并拒绝连接，系统配置无变化 |
| 用户取消系统授权 | 回到未连接，已导入配置保留 |
| 重复点击连接、连接中断开 | 最多一个受管实例，最终状态与用户最后操作一致 |
| 后台未安装、IPC 无权限、协议不兼容 | 分别报告，不把所有失败归为网络错误 |
| 关闭窗口、退出界面、重新打开 | 后台按选定行为运行，重新打开后显示真实状态 |
| 后台崩溃与重启 | 无重复实例，显示失败原因，可清理并恢复 |
| 配置切换或更新失败 | 旧版本仍可恢复，新旧路由不并存 |
| Wi-Fi 切换、断网、睡眠唤醒 | 状态有依据，恢复后可重连，无遗留实例 |
| 主动断开与卸载 | 删除本应用持有的设备、路由、socket 和后台注册，不误删其他 VPN |
| 与其他 VPN 同时存在 | 不覆盖默认路由或 DNS；冲突可解释，不能通过破坏其他配置继续启动 |
| 普通上网与 DNS 对照 | 连接前、中、后行为符合仅 Nebula 节点范围 |
| 诊断导出 | 不含私钥、原始配置、证书正文；节点地址等信息明确告知用户 |
| 多用户／伪造 socket／替换二进制 | 未授权调用与不可信执行目标被拒绝 |

联网验证需要两台测试节点与有效凭据。用户目前未提供这些资源，因此真实节点互通、授权、睡眠和清理测试均未执行。临时测试网络可验证机制，不能替代用户真实网络验收。

## 11. 风险、恢复与待验证决策

| 问题 | 应对与恢复 | 决策责任与时点 |
| --- | --- | --- |
| 无账号时后台注册或授权受限 | 先验证权限；失败保留导入与通信验证成果，不承诺自动提权 | 开发者在阶段一给出证据，用户决定账号或路线 |
| 后台权限过大 | 固定执行目标、受管目录、有限接口与调用者检查 | 开发者在阶段一完成设计与负面验证 |
| 网络不可用或 Lighthouse 不可达 | 本地界面仍能打开、查看配置与导出诊断；不依赖云控制面 | 开发者在阶段二验证错误分类 |
| 已知节点数量增长十倍 | 按需加载、限制刷新并发、日志限额，不全量高频刷新详情 | 开发者在阶段三按实际节点规模验证 |
| 配置更新损坏 | 保留已验证版本，失败不覆盖，断开后原子切换 | 开发者在阶段二、三验证 |
| 用户现有其他 Nebula 进程 | 检查受管身份与路由冲突，绝不接管或停止不属于本应用的进程 | 开发者在阶段一验证 |
| 未来迁移到 Network Extension | 保留配置 ID、连接接口和错误模型；后台适配仍是独立开发 | 用户在 iOS 或正式 macOS 分发前决定 |
| 撤回本机验证版 | 停止受管实例、清理受管路由、取消服务注册；配置默认保留，凭据删除需明确操作 | 开发者在首次系统安装前提供卸载方案 |

尚需用户确认的产品决策为：最低 macOS 版本、首版架构覆盖、到期提醒阈值、退出界面是否保持连接及正式分发方式。它们不阻碍文档保存，分别在创建工程、实现提醒与生命周期、准备发布前确认。

签名、授权和平台适配的限制必须如实记录，不用模拟状态或跳过清理来让界面表现为成功。完整技术实施计划在阶段一验证完成后收敛；本方案不把未验证选项写成确定能力。
