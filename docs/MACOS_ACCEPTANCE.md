# macOS 连接可靠性实机验收

对应 Issue #4。本文件是可执行验收步骤与记录模板，不代表各项已通过。隔离模型、退出探针、安装脚本替身与真实隧道验收分别记录。

## 执行前

安排可中断网络的测试窗口。记录 App、普通后台、root 组件、内核 SHA、macOS 版本、架构、签名方式与测试日期。备好已验证的 App、固定组件、受保护备份及一份可用配置；真实凭据不加入仓库。

先验证一个由管理员指定的其他 Nebula 节点可达；明确它仅是测试目标，不代表全网状态。记录系统上网、DNS、其他 VPN 的基线。确认如何在原版本恢复连接，失败时停止继续注入。

本机快照工具只读系统上下文：

```sh
umask 077
python3 scripts/acceptance-snapshot.py > /private/tmp/nebula-before.json
# 用户在 GUI 执行当前验收步骤后
python3 scripts/acceptance-snapshot.py > /private/tmp/nebula-after.json
```

快照包含系统版本、受管组件的 PID／UID、安装文件权限与哈希、各 utun 的路由数量。它不读取配置目录、证书、密钥或 socket 响应。netstat 原始文本中的地址仅短暂用于解析，不导出地址、主机名或进程参数。所有 utun 的数量只供比较，不能据此判断某条路由属于 Nebula，也不能单独证明清理成功。目标地址与具体受管接口的核验在本机完成，分享前脱敏。

短／长睡眠分别记录实际时长。A08/A09 的进程终止与 A11 故障注入仅在明确同意的窗口由开发者执行，不作为产品普通用户流程。A11 先验证隔离脚本回退，再在可恢复的测试机操作，禁止损坏当前机器唯一的可用组件来制造失败。

## 每个场景记录

- 场景 ID、开始／结束时间、操作人、环境和版本。
- 操作前后的 GUI 文本、组件 PID／UID、受管接口／路由观察、目标探测时间与结果。
- 自动恢复次数和结果、主动断开后至少 30 秒内有无重新连接。
- 是否有其他 VPN、系统上网／DNS 对照结果。
- 实际结果：通过／失败／未执行；证据位置、脱敏方式、失败 Issue 和回退结果。

发生未确认清理、额外实例、超范围路由或其他 VPN 受影响时，停止本轮注入，保留快照，先按原版本恢复。不能仅以 GUI 显示“未连接”判定清理通过。

## 2026-11-05 实机记录

环境：macOS 27.2，arm64；GUI 0.3.1（main 加 #28 修复，ad-hoc 签名）；内核 `fb4ef13`；本机已安装的 root helper 未替换，前后哈希不变。使用生产数据目录中的一份真实配置，以一个管理员指定的节点作为测试目标；它只代表这个节点，不代表全网。系统中配置了另一个 VPN 服务，但全程未连接；其他 utun 只有系统的 IPv6 路由，退出前后快照的路由计数一致。默认路由始终在物理网卡上。操作人是开发代理，通过 AppleScript／辅助功能操作 GUI，并用只读快照工具记录状态。地址、主机名和截图只保存在本机临时目录，不入库。

- **A01**：连接后关闭主窗口，进程和 utun 路由（2 条）保持不变。修复前，点击 Dock（reopen 事件）后不出现窗口，因此新建了 #28。修复后，reopen 重新打开主窗口，显示“隧道已启动”，进程与路由不变。
- **A02**：连接请求约 1 秒完成，一次辅助功能遍历约需 3 秒，无法在连接中途取消。迟到响应的处理由 `testCancelConnectRejectsLateStartedResponse` 覆盖，但这不是实机结果。
- **A08**：对普通后台发送 SIGKILL。3 秒内出现新的后台进程；root helper 的 PID 不变。事件依次为“旧连接清理已确认”和“隧道已启动”，只有一个受管隧道，目标节点 ping 收到 2/3。
- **A12**：GUI 主动断开后没有自动重连。正常退出约 2 秒内，GUI 和普通后台都已结束，受管 utun 路由清空。helper 的 PID 和哈希不变，默认路由仍在原网卡，外网访问正常。卸载需要管理员授权，本轮未执行。
- **节点测试（#25）**：在真实隧道上，GUI 内联结果收到 3/3、丢包 0%，与同时段系统 ping 的 3/3 一致。
- **A09**（main `39de32a` 构建，用户在场输入管理员密码）：在已连接时执行 `launchctl kickstart -k system/net.nebula.gui.helper`。root helper 的 PID 换新，安装文件哈希不变。普通后台随之由 GUI 重新拉起。GUI 事件在同一秒（重启后约 1 秒）依次记录“旧连接清理已确认”和“隧道已启动”。utun0 先降为 0 条路由，下一次采样恢复为 2 条，之后约 6 分钟保持稳定。恢复后只有一个 helper 和一个后台，目标节点 ping 收到 3/3，默认路由仍在原网卡。限制：辅助功能采样约 11 秒一次，无法排除 GUI 在约 1 秒的中断窗口内短暂显示旧状态。但事件顺序表明，GUI 是先确认清理再报告启动的。
- **A03–A07**：用户选择本轮不做睡眠、断网和切换网络。**A10** 需要用户在系统授权窗口中操作，单独记录。**A11** 只能在隔离测试机执行。
